# ALGOGO-107 로고 수직 정렬 보정 검증

## 변경 결과

- 공통 `Logo.tsx`의 Tenada 워드마크에 `relative top-1`을 적용해 글자 줄 상자가 아닌 실제 글자 형태를 기준으로 심볼과 시각 중심을 맞췄다.
- `167b6b7^:src/components/common/LogoWithText.tsx`에서 사용하던 Tenada 워드마크의 4px 하향 보정을 현재 공통 브랜드 로고에 복원했다.
- `sm`, `md`, `lg`의 심볼·글자 크기와 간격, Tenada 서체, 색상 상속은 유지했다. `showText={false}`인 심볼 단독 로고에는 보정이 적용되지 않는다.

## 정적 확인

- 심볼 PNG의 1254x1254 이미지 박스 안에서 알파 영역은 `(78, 156)`부터 `(1177, 1160)`까지이며, 보이는 영역의 세로 중심은 이미지 박스 중심보다 약 31px 아래에 있음을 확인했다.
- 현재 `Logo` 소비처를 확인했다. `sm`은 일반·랜딩 헤더, 모바일 메뉴, 랜딩·일반 푸터, 로그인 모바일, OAuth 상태에서 사용하고, `md`는 로그인 데스크톱에서 사용한다. `lg`는 공통 컴포넌트가 지원하는 크기로 함께 보정된다.
- 변경 파일 Prettier와 ESLint, 프로덕션 빌드 및 `git diff --check`가 모두 통과했다. 빌드에는 기존 대용량 chunk 경고만 남았다.

## 브라우저 검증 시나리오

루트 작업에서 다음을 실제 화면으로 확인한다.

1. 밝은 테마와 어두운 테마의 일반 헤더, 랜딩 헤더, 일반 푸터, 랜딩 푸터에서 `sm` 로고를 비교한다.
   - 심볼과 `알고고` 글자의 실제 보이는 영역이 같은 세로 중심에 놓여야 한다.
   - 워드마크가 Tenada로 표시되고 위아래가 잘리지 않아야 한다.
2. 로그인 화면을 데스크톱 너비와 모바일 너비로 각각 확인한다.
   - 어두운 배경의 흰색 `md` 로고와 밝은 배경의 primary 색상 `sm` 로고가 모두 같은 방식으로 정렬되어야 한다.
3. `Logo size="lg"`를 밝은 배경과 어두운 배경에서 확인한다.
   - `sm`, `md`와 동일하게 워드마크가 심볼보다 위로 떠 보이지 않아야 하며, 4px 보정으로 아래에 처져 보이거나 잘리지 않아야 한다.
4. 헤더 로고에 hover하고 모바일 메뉴를 연다.
   - 기존 확대 효과가 유지되고, 모바일 메뉴의 로고 정렬에도 차이가 없어야 한다.
5. `showText={false}`인 `components/common/Logo.tsx`의 심볼 단독 표시를 확인한다.
   - 워드마크 보정의 영향을 받지 않고 기존 위치와 크기를 유지해야 한다.

## 루트 브라우저 QA 결과

- 2026-09-11에 로컬 데이터가 연결된 홈을 어두운 테마와 밝은 테마로 전환해 헤더·푸터의 `sm` 로고를 확인했다. 심볼과 Tenada 워드마크의 보이는 중심이 같은 축에 놓였고 글자가 잘리지 않았다.
- 로그인 화면의 어두운 좌측 영역에서 `md` 로고를 확인했다. 4px 하향 보정 후 심볼과 워드마크가 같은 시각 중심에 놓였다.
- 테마 메뉴를 열고 라이트 항목을 선택해 전환 동작과 포커스 복귀가 유지되는 것을 확인했다.
