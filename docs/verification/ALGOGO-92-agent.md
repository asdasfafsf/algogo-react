# ALGOGO-92 에이전트 검증

## 구현 범위

- 로그인·회원가입 화면을 v2 분할 레이아웃으로 재구성하고 기존 Google/Kakao OAuth 진입 경로와 `destination` 복귀 값을 유지했다.
- OAuth 이동 중 버튼을 잠가 중복 요청을 막고 로그인·연결·연결 해제 콜백 화면에 처리 상태를 표시했다.
- `/me`에서 실제 사용자 조회가 끝나기 전 로딩 상태를 표시하고, 사용자가 없으면 편집 가능한 임시 프로필 대신 `/me` 복귀 정보가 포함된 로그인 안내를 표시했다.
- 프로필 이름·이미지 편집에 레이블, 저장 중 상태, 빈 이름 방지, 취소 복원, 실패 후 재시도 흐름을 적용했다.
- 연결 계정은 실제 `me.oauthList`로 표시하며 기존 연결·해제 확인과 마지막 계정 해제 경고를 유지했다.
- 제공되지 않는 통계·활동·외부 풀이 사이트 기능은 임의의 0 또는 빈 활동 그래프 대신 준비 상태로 표시했다.
- 프로필 이미지가 없는 경우 헤더에 외부 샘플 사진을 표시하지 않고 사용자 이름 기반 대체 이미지를 표시한다.

## 자동 검증

- 수정 파일 Prettier 적용: 통과
- 수정 파일 ESLint 자동 수정 및 전체 `src` ESLint 검사: 통과
- TypeScript `--noEmit`: 통과
- Vite 프로덕션 빌드: 통과
  - 기존 대형 번들 경고가 출력되며 빌드 결과에는 영향을 주지 않았다.
- 계정 도메인 계약 6개 assertion: 통과
  - OAuth 진입 URL과 `destination` 복귀
  - 잘못된 OAuth state의 기본 복귀 경로
  - 마지막 로그인 계정 해제 경고
  - 프로필 업데이트 요청의 소셜 계정 보존
- `git diff --check`: 통과

## 브라우저 확인

- 실제 로그인 계정으로 `/me` 사용자 정보 로드: 확인
- 이름 저장 후 새로고침 유지: 확인
- 편집 취소 시 기존 이름 복원: 확인
- 공백 이름 저장 비활성화: 확인
- 390px 모바일 화면에서 긴 정보와 프로필 구성의 가로 넘침 없음: 확인

Google/Kakao 제공자 화면을 거치는 로그인과 계정 연결·해제의 최종 결과는 외부 OAuth 및 백엔드 환경이 함께 필요한 흐름이므로 콜백 계약과 진입 URL까지만 로컬에서 검증했다.

## 최종 브라우저 회귀 검증

- 로그인/회원가입 화면 전환 시 문제 상세 destination 유지.
- 인증 code 없는 Google callback → 실패 안내 → 로그인 화면 복귀.
- 프로필 저장 요청만 한시적으로 차단한 실패 시나리오: 실패 안내 뒤 편집 모드와 입력 유지. 요청 차단은 해제했다.
- 실제 계정 헤더 로그아웃 직후 빈 본문 없이 guest 안내 표시.
- 세션이 있는 상태에서 프로필 조회 요청을 한시적으로 차단: 조회 실패와 다시 시도 표시. 차단 해제 후 다시 시도로 실제 프로필 복구.
- 사진 없는 사용자 헤더: 외부 샘플 얼굴 대신 이름 이니셜 표시.

## 검증 한계

- 로컬 임시 계정으로 실제 API를 검증했다. Google/Kakao 제공자 로그인 완료를 검증한 것은 아니다.
- 프로필 이미지 첨부는 Chrome 확장의 파일 URL 접근 권한 부족으로 첨부 단계에서 중단되었다. 업로드 성공으로 보고하지 않는다.
- 통계/활동/외부 풀이 사이트 데이터는 현재 제공되지 않는 기능으로 명시한다.
