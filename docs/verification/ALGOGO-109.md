# ALGOGO-109 홈·문제 목록 표현과 상호작용 검증

2026-09-11. 대상 경로는 홈(`/`)과 문제 목록(`/problem`)이며 두 경로 모두 현재 `App` 화면을 공유한다. `algogo-react-v2`는 읽기 전용으로 비교했고, 문제 제목·난이도·유형·상태·정답률·제출·출처와 검색·필터·정렬·페이지 이동 계약은 유지했다.

## 변경

### 장식과 문구

- 메인 캐러셀의 오른쪽 동심원 장식과 버튼처럼 보이던 비활성 `준비중` pill을 제거했다. 구현 진행 상황 대신 사용자가 계정 연동으로 얻을 수 있는 결과를 제목과 한 문장으로 안내한다.
- 빠른 탐색의 랜덤 도전·유형별 문제를 각각 둥근 카드와 아이콘 배경으로 반복하지 않고, 하나의 구획 안에 나뉜 예정 항목으로 묶었다. 비활성 항목은 `곧 열려요`로 안내하며 클릭 가능한 모양이나 hover를 갖지 않는다.
- 문제 목록 실패 상태의 원형 아이콘 배경과 빈 상태의 비활성 `문제 추가 준비 중` 버튼을 제거했다. 서버의 기술 오류 문구를 노출하지 않고, 실패·빈 결과에서 사용자가 할 수 있는 다음 행동만 직접 설명한다.
- 상태 아이콘, 난이도·유형 badge, 캐러셀 위치 표시는 데이터 의미나 조작 목적이 있으므로 유지했다.

### 상호작용 피드백

- 오늘의 문제 본문, 전체보기, slide 선택, 캐러셀 이동에 hover·focus-visible·active를 보완했다.
- 오늘의 문제가 10개 이상일 때 표시하는 현재 위치 카운터는 조작 대상이 아니므로 포커스·hover·키 입력 없이 `aria-live="polite"` 상태로만 알린다. 방향키 이동은 기존 캐러셀 루트가 담당한다.
- 문제 행 전체를 Tab으로 포커스하고 Enter로 열 수 있게 했다. 출처 버튼은 독립적으로 동작하며 행 열기 이벤트를 발생시키지 않는다. 출처가 없는 버튼은 disabled 상태에서 hover와 클릭 피드백을 내지 않는다.
- 정렬 이벤트를 `th`가 아닌 실제 정렬 버튼에 연결하고 hover·focus-visible·active 상태를 적용했다.
- 검색 버튼·입력, 페이지 크기, 난이도·유형·상태 필터, 숨김 토글, 적용·초기화, 활성 필터 제거, 페이지 이동에 상태별 색상 피드백을 추가했다.
- 밀집된 난이도·활성 필터에서 hover/active scale을 제거하고 색·테두리·명도 변화로 바꿨다. 캐러셀 화살표 배치와 열림 chevron 회전처럼 기능 상태를 나타내는 transform은 유지했다.

- `tests/*.mjs` 18개: 기존 계정·클립보드·API·도메인·에디터·실행·모달·문제 목록·문제 표시·v2 transport 회귀 검사 통과.
- `rtk git diff --check`: 공백 오류 없음.
- 개발 서버에서 `/tests/fixtures/home-problem-list.html`을 실제로 렌더링해 데이터·빈 결과·오류 상태 전환과 상호작용을 확인한다. fixture도 앱과 같은 `ModalProvider` 안에서 렌더링해 필터 모달 의존성을 빠뜨리지 않는다.

## 루트 브라우저 확인 결과

- 실제 `/` 화면에서 캐러셀 구조, 빠른 탐색, 문제 검색·필터·표·페이지 이동을 확인했다. 난이도 선택과 적용 뒤 목록 결과가 바뀌며 메뉴가 정상적으로 닫혔다.
- fixture를 실제 렌더링해 오늘의 문제와 문제 목록을 각각 `data`, `empty`, `error`로 전환했다. 빈 결과 안내와 오류 안내·다시 시도가 각 영역 안에서 깨지지 않고 표시됐다.
- 390×844 모바일에서 전체 문서 너비가 390px로 유지됐고, 필터는 줄바꿈되며 표는 자체 가로 스크롤 영역을 유지했다. 예정 항목은 `cursor: auto`이고 Tab 대상이 아니었다.
- 데스크톱과 모바일 모두 캐러셀의 동심원 장식과 가짜 버튼이 사라졌으며, 화면 문구는 구현 용어 없이 사용자가 얻는 결과와 다음 행동을 설명한다.
