# ALGOGO-100 다이얼로그 검증

## 변경 전 재현

`tests/fixtures/dialog-layers.html`에서 실제 모달 컴포넌트를 인증 없이 열어 확인했다.

- 화면 설정 → 에디터 테마 선택 메뉴 → Esc 1회: 선택 메뉴와 화면 설정 창이 함께 닫혔다.
- 부모 대화상자 → 알림 두 개 열기 → 마지막 확인 클릭: 두 알림이 모두 사라지고 마지막 알림의 Promise만 완료되었다.
- 동시에 열린 두 알림이 모두 `aria-hidden=true`가 되어 접근 가능한 확인 버튼을 찾지 못했다.

## 검증 범위

이 fixture는 실제 Dialog·Select·에디터 설정·테스트 케이스·템플릿 모달을 사용한다. 인증 성공이나 서버 저장 성공을 모사하지 않는다. UI 레이어와 로컬 입력 보존 검증을 실제 백엔드 연동 검증과 구분한다.

## 변경 후 결과

- 화면 설정 안 Select → Esc: Select만 닫히고 해당 선택 버튼에 포커스가 돌아왔다. 두 번째 Esc에서 설정만 닫히고 원래 열기 버튼으로 복귀했다.
- 부모 입력 변경 → 자식 Alert → Esc 또는 바깥 클릭: 부모 창과 입력이 유지되고 자식 알림 열기 버튼으로 복귀했다.
- 동시 Alert 두 개: 최상단만 접근성 트리에 노출되고 Esc 두 번으로 두 번째 → 첫 번째 순서로 닫혔다. 각 Promise도 해당 순서로 한 번씩 완료되었다.
- 부모 창의 마지막 닫기 버튼에서 Tab: 포커스가 첫 입력으로 순환했다. 부모 종료 후 선언형 DialogTrigger로 복귀했다.
- Confirm 취소와 확인: 각각 false/true가 반환되었다.
- 템플릿 설명 입력 → 빈 이름 검증 오류 → Alert Esc: 부모 폼의 설명과 Monaco 코드가 유지되고 추가 버튼의 처리 중 상태가 해제되었다. 서버 저장 요청은 하지 않았다.
- 테스트 케이스 입력/예상 출력 편집 → Esc → 재열기: 로컬 값이 유지되었다. 검증 후 추가한 케이스를 삭제했다.
- 토스트 자동 종료 후에도 함께 연 Alert가 남았다. 로딩 창은 Esc와 바깥 클릭으로 닫히지 않고, 종료 요청 후 원래 버튼으로 포커스가 돌아왔다.
- 실제 5175 홈에서 Cmd+K 검색 포커스, Enter 검색, Esc 입력 포커스 해제 및 로컬 문제 조회를 확인했다. 검색어를 정리했다.
- 390px 모바일 메뉴 Sheet의 Esc 종료와 메뉴 열기 버튼 포커스 복귀를 확인하고 뷰포트 설정을 복원했다.

## 정적 검증

- 전체 ESLint, TypeScript, Vite 프로덕션 빌드 통과. 기존 대형 chunk 경고는 남아 있다.
- `tests/*.mjs` 17개 파일 통과. 이후 컨트롤러 테스트에 대기 로딩의 마운트 전 취소, 중복 커밋 통지 사례를 추가하고 해당 테스트를 재실행했다.
- fixture는 개발 서버에서만 열어 사용하며 프로덕션 앱 경로에 연결하지 않았다. fixture 파일은 저장소 ESLint의 src 범위에 포함되지 않는다.
- fixture를 포함한 별도 TypeScript 검사도 통과했다.
