# ALGOGO-93 에이전트 검증

## 범위

- 문제 목록의 유형·상태 선택기와 활성 필터 표시
- 데스크톱·모바일 페이지 탐색
- 랜딩, 오류, 404 화면
- 기존 문제 목록 API 요청과 필터 직렬화 계약 보존

## 자동 검증

- `node node_modules/typescript/bin/tsc --noEmit`: 통과
- `node node_modules/eslint/bin/eslint.js './src/**/*.{ts,tsx,js,jsx}'`: 통과
- `node --test tests/problem-level-selection.mjs tests/problems-domain.mjs tests/problems-v2-transport.mjs`: 13개 통과
  - 필터 적용·제거와 페이지 전이 규칙 포함
  - 기존 v2 API 배열 쿼리 직렬화 포함
- `node node_modules/vite/bin/vite.js build`: 통과
  - 기존 대형 번들 청크 경고만 발생

테스트 실행 중 Vite HMR용 `24678` 포트가 이미 사용 중이라는 메시지가 출력됐지만, 테스트용 서버는 정상 기동되어 모든 검증이 통과했다.

## 브라우저 인계 확인 항목

상위 에이전트의 통합 브라우저 검증에서 아래 항목을 확인한다.

- 320px와 390px에서 필터 버튼, 가로 스크롤 표, 페이지 이전·다음 버튼이 화면 밖으로 잘리지 않는지 확인
- 유형 검색, 검색 결과 전체 선택, 적용, 닫기 시 미적용 선택 취소, 확인 후 초기화 확인
- 상태 선택과 활성 필터 개별 제거·전체 초기화가 실제 목록 요청에 반영되는지 확인
- 랜딩의 가입·로그인·문제 목록 링크와 자세히 알아보기 스크롤 확인
- `/error?message=...`에서 전달된 메시지가 인라인으로 한 번만 표시되는지 확인
- 오류·404 직접 진입에서 이전 페이지 버튼이 문제 목록으로 안전하게 이동하는지 확인

## 브라우저 회귀 수정

- 활성 필터 배지에서 유형을 제거한 뒤 닫힌 유형 트리거에 이전 선택 개수가 남는 현상을 수정했다. 난이도 트리거에도 같은 적용 상태와 드래프트 분리를 적용했다.
- 유형 검색 입력에 접근 가능한 이름을 추가했다.
- 비로그인 상태에서는 개인 풀이 상태 필터 대신 `/login?destination=/problem` 안내 링크를 표시하고, 로그아웃 시 남아 있던 상태 필터를 제거한다.
- 랜딩의 예시 문제와 난이도에 예시임을 표시하고, 버튼처럼 보이던 비활성 표시는 `샘플 화면` 텍스트로 변경했다.
- 320px 화면에서 난이도 티어 행이 가로로 넘치지 않도록 레이블, 단계 버튼, 간격을 모바일에서 축소했다.

## 남은 연동 이슈

- 단일 상태 선택은 현재 `states=SOLVED`처럼 문자열 하나로 직렬화된다. 백엔드 DTO가 `states`를 배열로 변환하지 않은 채 저장소에서 `states.filter`를 호출하므로 요청이 실패하고, 프론트 오류 처리에서 이전 목록이 남는다.
- 단일 상태도 배열로 전달하는 transport 보정과 문제 목록 실패 상태 처리는 별도 이슈에서 다룬다.

## 루트 브라우저 확인

- 실제 유형 검색/단일 선택 적용으로 1→0개, 활성 배지 제거로 0→1개 및 트리거 선택 수 제거 확인.
- 로그아웃 후 상태 필터가 로그인 안내 링크로 전환하고 destination=/problem 보존.
- 320px 난이도 팝오버 내부 단계와 전체 버튼이 가로 잘림 없이 표시. document.scrollWidth=320 확인(표 내부 가로 스크롤은 유지).
- 오류 페이지 문구 단일 표시와 홈 복귀, 직접 진입 404 뒤로가기의 홈 복구 확인.
- 소개 화면 자세히 알아보기 섹션 이동 확인. 샘플 카드 예시 표기를 보강.
- 로그인 상태 단일 풀이 필터는 서버 scalar/array 계약 오류 발견. ALGOGO-96에서 transport/오류 목록 처리 수정 및 재검증.
