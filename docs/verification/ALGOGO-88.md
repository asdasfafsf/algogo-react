# ALGOGO-88: 오늘의 문제 화면 검증

## 재현과 기준

- 기준: PR #124의 오늘의 문제 화면에는 예전 흰색 통계 카드와 탐색 배치가 남아 있었다.
- `TodayProblemCard`는 호스트가 `localhost`가 아니면 운영 사이트로 문제를 열었다. `127.0.0.1:5175` 로컬 테스트에서도 운영 사이트로 이동하는 경로를 확인했다.
- 디자인 기준: 읽기 전용 `algogo-react-v2`의 `http://127.0.0.1:5176/problems/today` 실제 화면.
- 기준 구성: 중앙 날짜 탐색, 문제 진행 표시, 선택 문제의 넓은 요약 카드, 하단 전체 목록. 실제 데이터는 기존 프론트의 오늘의 문제·문제 상세 API를 사용한다.

## 실행 결과

- [x] 실제 로컬 API의 오늘의 문제 3개와 선택한 문제의 상세 본문이 표시됨을 확인했다.
- [x] 날짜 이전 버튼으로 `?day=-1` 이동 → 9월 9일과 빈 상태가 표시되고, 다음 날짜·오늘 복귀 탐색이 제공됨을 확인했다.
- [x] 문제 요약 링크를 클릭해 `127.0.0.1:5175/problem/<검증 문제 UUID>` 새 탭이 열리고 실제 본문·에디터가 로드됨을 확인했다. 검증 탭은 닫았다.
- [x] 진행 표시에서 문제 1 선택 후 ArrowRight 두 번 → 문제 3으로 선택·DOM 포커스·본문·링크가 함께 바뀜을 확인했다. 최초 검증에서 포커스가 이전 탭에 남는 문제를 발견해 수정한 뒤 재검증했다.
- [x] 로컬 API의 영문 난이도 텍스트 대신 숫자 난이도로 브론즈 5·4·3이 표시됨을 확인했다. 미해결 문제에는 추가 상태 배지를 붙이지 않고 목록의 원형 아이콘을 유지한다.

- [x] 날짜 선택 팝오버를 열고 Escape를 누르면 닫히며 날짜 선택 버튼으로 포커스가 복귀한다.
- [x] 390×844 모바일에서 요약 카드와 목록이 화면 안에 들어가며 문서 가로 넘침이 없다.
- [x] 실제 백엔드 DTO의 날짜 허용 범위가 -30~0임을 확인했다. 날짜 입력과 이전 버튼을 이 범위로 제한하고, 잘못된 URL 날짜를 오늘로 정규화했다.

- [x] ALGOGO-87 머지 후 실제 통합 화면에서 공통 메뉴·난이도 배지·중앙 날짜/진행 표시·요약 카드/하단 목록을 재확인했다.
- [x] 통합 상태에서 TypeScript, Vite build, 전체 회귀 검사 26/26과 도메인 경계 25개 모듈 통과. 대상 ESLint/format과 diff check도 통과했다.
- [x] 검증 전용 문제 21개·오늘의 문제 3개를 삭제했고 원래 문제 1개가 유지됨을 확인했다. 새 조회에서 오늘의 문제 빈 상태, 홈의 빈 카드와 전체보기, 기존 문제 목록이 정상 표시된다.

## 테스트 데이터

ALGOGO-87과 같은 로컬 테스트 DB의 임시 오늘의 문제 3개를 사용한다. 날짜 이동으로 빈 상태를 확인하고, 전체 검증 후 이번 검증에서 만든 데이터만 제거한다. 실제 운영 오늘의 문제 데이터나 외부 OAuth 성공을 검증한 것은 아니다.
