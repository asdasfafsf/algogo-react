# ALGOGO-115 템플릿 초기화 실패 검증

## 변경

- 비로그인 상태에서는 Monaco 편집기는 표시하되, 사용자 정보·access token·refresh token이 모두 없으면 초기화 요청을 시작하지 않는다.
- 초기화 중 설정 API가 401이면 템플릿과 저장 코드 요청을 이어서 보내지 않는다.
- 템플릿 응답은 정상 템플릿, 401, 비정상 상태 코드, 본문 누락·형식 오류, 요청 예외를 별도 결과로 구분한다. 성공 상태로 바꾸거나 누락된 본문을 추정하지 않는다.
- 네트워크 응답이 없는 Axios 오류는 거부로 유지하고, 초기화는 이를 처리해 Promise rejection이 밖으로 전파되지 않도록 한다.
- 인증된 세션의 초기화가 실패하면 기술 상세 대신 “다시 로그인” 또는 “새로고침해 다시 시도” 안내를 토스트로 표시한다.

## 자동 검증

- `rtk proxy node tests/editor-template-initialization.mjs`: 정상 템플릿의 기본 코드 선택, 비로그인 세션 차단, 401, 비정상 응답 본문, 요청 실패 결정을 검증했다.
- `rtk proxy node tests/code-editor-initialization.mjs`: 실제 `CodeEditorStore.initialize`에 API 응답을 주입해 정상 초기화, 템플릿 401 이후 저장 코드 요청 중단, 템플릿 네트워크 실패 이후 저장 코드 요청 중단을 검증했다.
- 변경 파일 ESLint·Prettier, 전체 `pnpm lint`, TypeScript/Vite 프로덕션 빌드, `git diff --check`를 통과했다.

## 루트 브라우저 QA 시나리오

1. 로그아웃 상태에서 문제 상세를 열고, 네트워크 패널에 코드 설정·템플릿·저장 코드 요청이 생기지 않는지 확인한다.
2. 코드 영역은 ALGOGO-108의 로그인 안내와 함께 표시되고, 콘솔에 unhandled rejection이 없는지 확인한다.
3. 로그인 상태에서 정상 템플릿이 기본 코드로 적용되는지 확인한다.
4. 템플릿 요청을 401 또는 네트워크 실패로 만들고, 기술 예외 대신 짧은 로그인·새로고침 안내가 보이며 콘솔에 unhandled rejection이 없는지 확인한다.

## 루트 브라우저 확인 결과

- 로그아웃 저장소를 비운 뒤 실제 문제 상세를 열어 Monaco 편집기와 로그인 안내가 함께 표시되는 것을 확인했다.
- 성능 리소스 목록에서 `/api/v1/code/` 요청이 0건임을 확인했다. 로그아웃 상태에서는 설정·템플릿·저장 코드 초기화 요청이 시작되지 않았다.
- 같은 시점의 런타임 예외는 0건이었고, 기존에 반복되던 `defaultList` unhandled rejection이 재현되지 않았다.
