# ALGOGO-89 난이도 드롭다운 내부 검증

## 기준과 재현

- 기준 dev: `22760ec` (ALGOGO-88 머지).
- 읽기 전용 v2의 DifficultySelector 실제 화면: 팝오버 360px, 티어별 한 줄, 32×32px 숫자 1~5, 전체 선택, 선택 개수/초기화 헤더.
- 기존 프론트는 트리거만 바뀌고 내부 큰 칩과 초기화/적용 버튼은 예전 구성으로 남아 있었다.
- 기존 난이도 API 값과 적용 전 임시 선택/취소, 초기화 확인 동작을 보존한다. v2의 mock 난이도 숫자 매핑은 복사하지 않는다.

## 검증 시나리오

1. 기본 팝오버 폭, 6개 티어 행과 숫자 버튼 간격을 v2와 비교한다.
2. 브론즈 1 개별 선택 후 전체 선택/전체 해제를 확인한다.
3. 브론즈 5만 적용하면 로컬 난이도 1 문제를 유지하고, 브론즈 1만 적용하면 제외하는지 확인한다.
4. 적용 전 Escape로 닫고 다시 열었을 때 적용된 선택이 복원되는지 확인한다.
5. 초기화 확인을 취소하면 선택을 유지하고 승인하면 목록 필터가 제거되는지 확인한다.
6. 모바일에서 전체 행과 적용 버튼에 접근하고 문서 가로 넘침이 없는지 확인한다.

## 결과

- [x] 실제 화면에서 팝오버 360px, 숫자 버튼 32×32px, 티어별 1~5/전체 선택과 색상·선택 개수·초기화를 기준과 비교했다.
- [x] 개별 선택은 그룹의 mixed 상태, 전체 선택은 5개 checked, 재선택은 전체 해제를 표시한다.
- [x] 브론즈 5 적용 시 기존 로컬 문제 1개, 브론즈 1로 연속 변경 시 0개, 초기화 승인 후 1개 복귀를 확인했다.
- [x] 적용 전 추가한 실버 1을 Escape로 취소하면 원래 적용된 브론즈 1만 복원된다. 초기화 확인 취소 시 선택이 유지된다.
- [x] 알 수 없음(value 0) 적용은 로컬 결과 0개, 초기화 승인 후 원래 목록으로 복귀한다.
- [x] 1280×720에서 팝오버를 가용 높이에 제한해 적용 버튼이 보인다. 390×844에서 모든 티어/적용에 접근 가능하고 문서 가로 넘침이 없다. 테스트 후 화면 크기와 선택을 원복했다.
- [x] 검증 중 발견한 동일 페이지 객체 재사용으로 두 번째 필터부터 재조회가 누락되는 문제를 수정하고 반복 변경을 재검증했다.
- [x] 별도 ALGOGO-90에서 현재 API의 배열 파싱에 맞게 쿼리 전송을 수정한 뒤 통합 검증했다.

대상 ESLint, TypeScript, Vite build, 전체 `tests/*.mjs` 31/31, diff check가 통과했다. 백엔드 및 v2 레퍼런스 파일은 변경하지 않았고 새 테스트 데이터도 만들지 않았다.
