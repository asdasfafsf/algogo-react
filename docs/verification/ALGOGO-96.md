# ALGOGO-96 문제 상태 필터와 목록 오류 복구 검증

## 재현과 원인

- 단일 상태 필터는 `states=SOLVED`처럼 쿼리 값 하나로 전송되어 백엔드에서 문자열로 파싱됐다. 백엔드 `InquiryProblemsSummaryDto.states`에는 배열 변환이 없고 저장소는 `states.filter`를 호출하므로 단일 상태 요청이 실패했다.
- 문제 목록 스토어는 응답 상태와 payload를 확인하지 않고 성공 데이터로 간주했다. 오류 응답이나 요청 예외가 발생하면 이전 목록과 개수가 화면에 남았고, 사용자에게 실패와 빈 검색 결과를 구분할 방법이 없었다.
- 여러 필터 요청이 겹치면 먼저 시작한 요청이 늦게 완료되면서 최신 필터의 목록·오류·로딩 상태를 덮을 수 있었다.

## 구현

- 단일 `states`를 `states=SOLVED&states=SOLVED`처럼 같은 repeat 키 두 개로 직렬화해 백엔드에서 배열로 파싱되도록 했다. 원본 요청 객체와 다중·빈 배열 직렬화는 유지했다.
- 문제 목록 응답의 상태 코드, 목록 배열, 전체 개수를 확인한다. 비정상 응답과 예외에서는 이전 목록, 전체 개수, 최대 페이지를 초기화하고 사용자용 오류 상태를 설정한다.
- 각 목록 요청에 순서를 부여해 최신 요청만 목록·오류·로딩 상태를 갱신한다. 오래된 성공과 실패가 늦게 도착해도 최신 결과를 덮지 않는다.
- 오류 화면에 안내와 같은 조건의 다시 시도 버튼을 제공했다. 재시도 성공 시 오류를 해제하고 목록을 복구한다.
- 검색 결과가 없을 때 아직 구현되지 않은 문제 추가 동작은 비활성 `문제 추가 준비 중` 문구로 표시하고 관련 모달 훅 의존성을 제거했다.

백엔드 코드와 공통 API 인터셉터는 변경하지 않았다.

## 루트 실제 브라우저 검증

루트 에이전트가 통합 서버에서 아래 항목을 확인하고 결과를 이 섹션에 기록한다.

- [ ] 로그인 상태에서 풀이 상태 하나를 선택했을 때 실제 요청이 repeat `states` 두 개를 포함하고 목록이 정상 갱신되는지 확인
- [ ] 문제 목록 요청 실패 시 이전 목록이나 `조건에 맞는 문제가 없습니다`가 표시되지 않고 오류 안내와 다시 시도가 표시되는지 확인
- [ ] 다시 시도 성공 시 오류 안내가 사라지고 현재 필터 조건의 목록과 개수가 복구되는지 확인
- [ ] 검색 결과가 없을 때 비활성 `문제 추가 준비 중` 문구가 표시되는지 확인
