# ALGOGO-86 UI 전환 검증

검증일: 2026-09-10. 프론트 전용 변경. 대상은 ALGOGO-86 워크트리, 로컬 Vite 5175, 로컬 Nest 3001, 전용 테스트 DB다.

## 보존 경계

- `src/domain`, `src/application`, `src/api`, `src/zustand`, `src/Router.tsx`는 기준 dev와 차이가 없다.
- UI hook 변경은 사용하지 않는 이벤트 인자 제거와 확인창 호출 전 강제 blur 제거뿐이다. 초기화 확인 결과와 저장·실행 규칙은 유지한다.
- Monaco 편집기, MathJax 문제 렌더링, 기존 화면 크기 저장/드래그 구조는 유지한다.
- 메인은 기존처럼 공지 슬라이드 한 개를 담은 캐러셀이다. 슬라이드 데이터 구조를 고정 카드로 대체하지 않는다.
- 공통 버튼·입력·선택·메뉴·탭·표·모달·페이지 이동·카드 등의 활성 사용처를 shadcn/Radix 기반으로 연결했다. 파일 선택 input은 네이티브 계약을 유지한다. 구형 경로는 props 호환 계층으로 남는다.

## 검증 환경의 한계

- 인증된 UI 검증은 실제 로컬 JWT를 발급한 폐기용 테스트 계정으로 수행했다. Google/Kakao OAuth 자체의 성공, 계정 연동·해제, 이미지 업로드, 외부 사이트 제출·채점 성공은 이번 검증에 포함하지 않았다.
- 로컬 코드 실행 요청은 기존 백엔드 실행 오류를 반환한다. 새 UI가 오류 알림을 표시하는 것은 확인했지만 성공 실행으로 보고하지 않는다. 기존 백엔드 템플릿 수정 검증 오류도 이 프론트 변경에서 해결하지 않는다.
- 오늘의 문제는 로컬 데이터가 없어 빈 상태만 실제 연동 검증했다. 데이터가 있는 날짜 이동·진행률 규칙은 기존 도메인 회귀 테스트로 확인한다.
- 모든 입력 조합과 외부 서비스의 전체 경로를 검증했다는 의미는 아니다. 확인한 경로와 미검증 경로를 위 표와 같이 구분한다.

## 캐러셀 fixture 재현

개발 서버에서 `/tests/fixtures/carousel.html`을 연다. 위는 자동 재생/반복, 아래는 수동/비반복이며 각각 직접 자식 슬라이드 세 개를 사용한다. 원래 앱 라우트와 production 진입점에는 연결하지 않는다. Embla의 전환 곡선은 기존 CSS 애니메이션과 다르며 디자인 변경 범위에 해당한다.
