# ALGOGO-98 로고 공통 적용 검증

## 구현 범위

- Image Gen으로 제작한 투명 PNG 심볼을 공통 브랜드 에셋으로 적용했다.
- 공통 `Logo`의 심볼 크기를 32/44/64px, 한글 워드마크를 Pretendard 700의 24/32/48px로 통일했다.
- 기존 Header, Landing Header/Footer, Login, OAuth 콜백 상태와 레거시 Footer가 같은 브랜드 컴포넌트를 사용하도록 연결했다.
- 기존 홈 링크와 클릭 경로를 유지했다.
- 심볼 이미지는 워드마크 옆에서 장식 이미지로 처리하고, 심볼만 표시할 때는 `알고고`라는 접근 가능한 이름을 제공한다.
- 브라우저 파비콘이 새 PNG 심볼을 사용하도록 했다. 기존 `favicon.svg`와 `favicon.ico` 파일은 삭제하지 않았다.

## 디자인 대조 기록

확정 에셋은 `public/brand/algogo-mark.png`이며, 1254x1254 RGBA 투명 PNG 원본을 그대로 사용했다. 코드에서 픽셀, 색상 필터, 대체 SVG로 재현하지 않았다.

- 심볼 형태: 열린 각진 G, 코드 브래킷, 오른쪽 사각 노드가 원본과 동일하다.
- 색상과 투명도: cobalt blue 심볼과 투명 배경을 그대로 사용한다.
- 심볼 여백: 원본 내부 여백을 고려해 Header에서 32px 박스로 표시한다.
- 워드마크: 한글 `알고고`를 코드 텍스트로 유지하며 기존 Pretendard로 읽기 쉽게 표시한다.
- 레이아웃: 새 문구나 기능을 추가하지 않고 기존 로고 영역의 크기와 간격만 통일한다.

## 루트 시각 검증 결과

- 생성 심볼 원본과 CUA 화면 캡처를 `view_image`로 직접 확인했다. 원본은 1254×1254이며 UI 전체 시안이 아니라 독립 심볼이다. 실제 UI는 1280×720, 390×844, 320×720에서 확인했다. 원본 이미지의 naturalWidth 1254와 CSS 32/44px 표시를 확인했다.
- 메뉴·본문·푸터 textContent를 적용 전후 비교했고 모두 일치했다. 홈 링크와 모바일 메뉴의 로그인 이동을 실제 클릭해 확인했다. 메인 캐러셀과 태그에는 변경이 없다.
- 라이트·다크에서 원본 청색 심볼, 24px/700 워드마크, 간격, 정렬, 배경 투명도, 모바일 잘림을 비교했다. 320px 안정화 후 document scrollWidth는 320px로 페이지 넘침이 없었다.
- 발견/수정: 데스크톱 로그인 청색 패널에서는 청색 로고의 대비가 부족했다. 패널 배경만 #101a2d로 바꾼 뒤 다시 캡처해 심볼·흰 워드마크 대비를 확인했다. 이는 사용자의 적절한 디자인 개선 허용에 따른 의도적 변경이며 폼/문구/구조는 그대로다.
- 파비콘 link가 새 PNG를 단독 참조하며 동일 이미지의 로드/원본 크기를 확인했다. OS별 탭 아이콘 캐시 갱신까지 보장하지는 않는다.
- 레거시 Footer는 현재 확인한 경로에서 직접 표시되지 않아 공통 어댑터 연결과 타입/빌드로 검증했다. 외부 OAuth 로그인 성공은 이번 브랜드 검증 범위가 아니다.
- 수정한 브랜드 범위에서 남은 시각 불일치는 발견되지 않았다. 생성 도구는 기본 제공 Image Gen이며 프롬프트와 선택 이유는 ADR에 기록했다.
- 검증용 탭·viewport override·임시 화면 캡처는 정리하며 사용자 테마는 기존 시스템 설정으로 복귀한다.
