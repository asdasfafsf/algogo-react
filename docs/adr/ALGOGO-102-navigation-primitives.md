# ALGOGO-102: 탭과 캐러셀 탐색 책임

## 문제

오늘의 문제 탭은 별도의 ref 배열과 키 이벤트로 포커스 이동을 구현해 `Home`/`End` 탐색과 `tab`-`tabpanel` 연결이 빠져 있었다. 캐러셀은 반대로 루트의 캡처 이벤트가 입력 요소와 탭 등 자식 컨트롤의 방향키까지 소비했다. 두 컴포넌트 모두 기존 디자인과 외부의 선택 상태 계약은 유지해야 했다.

## 검토한 대안

| 대안                       | 설명                                                     | 장점                                      | 단점                                                                         |
| -------------------------- | -------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------- |
| 컴포넌트별 수동 탐색 유지  | 현재 이벤트 처리에 빠진 키와 ARIA 속성을 추가한다        | 변경량이 작다                             | roving focus와 ID 연결을 계속 직접 관리하고, 표준 동작 누락이 반복될 수 있다 |
| 기존 primitive에 탐색 위임 | 탭은 Radix Tabs, 캐러셀 이동 상태는 Embla API를 사용한다 | 검증된 키보드·ARIA·경계 상태를 재사용한다 | 기존 마크업을 primitive 구조에 맞춰 연결해야 한다                            |
| 공통 탐색 계층 추가        | 탭과 캐러셀을 감싸는 새 탐색 훅을 만든다                 | 동작을 한곳에서 통제할 수 있다            | 서로 다른 위젯 규칙을 한 추상화에 섞고 기존 라이브러리와 책임이 중복된다     |

## 결정

탭의 선택·포커스·ARIA 연결은 기존 shadcn/Radix Tabs에, 캐러셀의 이동 가능 상태는 기존 Embla API에 위임한다.

## 이유

프로젝트에 이미 두 primitive가 있고 각 위젯의 표준 동작을 제공하므로 별도 탐색 계층의 유지 비용이 필요하지 않다. 캐러셀 루트는 방향에 맞는 키만 처리하고 자식 대화형 요소의 이벤트는 건드리지 않아 각 컨트롤의 고유 키보드 동작을 보존한다. 스타일과 선택 인덱스는 기존 컴포넌트가 계속 소유해 화면과 비즈니스 상태 계약을 유지한다.
