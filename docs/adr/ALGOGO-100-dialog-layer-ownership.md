# ALGOGO-100: 다이얼로그 레이어 소유권

## 문제

각 모달 훅과 컴포넌트가 전역 `Escape` 리스너와 `top/pop` 규칙으로 닫을 대상을 판단했다. Radix Dialog의 레이어 처리와 이 규칙이 함께 동작하면서 한 번의 `Escape`가 자식과 부모를 모두 닫거나, 동일 key 인스턴스가 함께 제거될 수 있었다. 같은 이벤트에서 다이얼로그를 둘 이상 열면 여러 Radix 포털이 한 커밋에서 마운트되어 각각의 `hideOthers` 처리가 상대 다이얼로그까지 숨겼다. 이때 최상단 다이얼로그까지 `aria-hidden`이 되어 접근성 트리에서 사라졌다.

## 검토한 대안

| 대안                                          | 장점                                                                    | 단점                                                                |
| --------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 전역 모달 stack을 보완한다                    | 기존 `top/pop` 호출부를 적게 바꾼다                                     | Radix의 `DismissableLayer`와 포커스 관리 규칙을 계속 중복한다       |
| `flushSync`로 각 `push`를 즉시 렌더한다       | 같은 이벤트의 동시 마운트를 막는다                                      | React effect나 비동기 콜백에서 호출될 때 제약과 경고가 생길 수 있다 |
| 인스턴스별 완료 함수와 커밋 대기열을 사용한다 | 닫기는 Radix에 맡기면서 동일 key 결과를 분리하고 순차 마운트를 보장한다 | 연속 생성된 다이얼로그가 각각 한 커밋씩 늦게 렌더된다               |

## 결정

각 registry 항목에 고유 ID와 전용 `resolve/reject`를 부여하고, 연속 생성 항목은 이전 렌더 커밋을 확인한 뒤 하나씩 등록한다. 이 대기열은 열기 시점만 분리하며 어느 다이얼로그를 닫을지는 판단하지 않는다.

## 이유

닫기 대상과 포커스 trap은 Radix가 실제 레이어 기준으로 판단할 수 있다. 비즈니스 로직은 자신이 연 모달의 결과만 받으며, 같은 key를 재사용해도 다른 인스턴스에 영향을 주지 않는다. 커밋 대기열은 닫기 순서를 판단하지 않고 마운트 시점만 분리하므로 별도의 dismiss stack을 만들지 않는다.
