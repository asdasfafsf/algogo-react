# ALGOGO-103: 클립보드 피드백 소유권

## 문제

복사 버튼은 브라우저 클립보드 쓰기의 성공 여부를 사용자에게 보여 주지 못했고, 실패한 Promise가 이벤트 처리 밖으로 전파될 수 있었다. 마우스를 벗어날 때만 상태를 초기화해 키보드 사용자는 피드백이 계속 남을 수 있었으며, 클릭 직후 Radix Tooltip이 닫히면 성공 여부도 확인할 수 없었다.

## 검토한 대안

| 대안                                                   | 설명                                                       | 장점                                                | 단점                                           |
| ------------------------------------------------------ | ---------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------- |
| 버튼에서 hover, focus, Escape와 피드백을 모두 관리한다 | 자체 상태와 이벤트로 툴팁을 구현한다                       | 클릭 결과를 직접 제어할 수 있다                     | Radix의 포커스와 dismiss 규칙을 중복 구현한다  |
| Radix Tooltip을 무제어로 둔다                          | 복사 상태만 아이콘과 안내 문구로 표시한다                  | 변경 범위가 작다                                    | 클릭 후 툴팁이 닫히면 즉시 피드백을 볼 수 없다 |
| 클릭 결과 동안만 Tooltip을 제어한다                    | hover, focus, Escape는 Radix에 전달하고 클릭 피드백만 연다 | 기존 접근성 동작을 유지하면서 결과를 즉시 보여 준다 | Tooltip wrapper에 제어 props가 추가된다        |

## 결정

클립보드 쓰기는 typed helper로 분리하고, 복사 결과가 나온 뒤 짧은 시간 동안만 Radix Tooltip을 제어한다.

## 이유

클립보드 API의 성공·실패는 helper의 Promise로 한곳에서 처리해 원문 그대로의 쓰기와 실패 테스트를 보장한다. Tooltip의 hover, focus, Escape 처리와 포커스 정책은 Radix에 남기고, 컴포넌트는 클릭 결과와 inline `aria-live` 안내만 소유한다.
