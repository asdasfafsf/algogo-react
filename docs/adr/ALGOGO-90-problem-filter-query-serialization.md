# ALGOGO-90: 문제 필터 쿼리 직렬화

## 문제

프론트엔드는 배열을 `levelList[]=5` 형태로 직렬화했지만, 현재 API의 단순 쿼리 파서는 이를 `levelList` 배열로 전달하지 않는다. 서버 DTO는 `levelList`가 배열일 때만 숫자 필터로 변환하므로 단일 난이도 선택이 무시됐다.

## 검토한 대안

| 대안                                                    | 판단                                                                                                     |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 백엔드 DTO가 대괄호 키와 단일 값을 모두 처리하도록 변경 | 다른 클라이언트의 계약까지 넓히며 이번 프론트 이슈 범위를 벗어나 제외했다.                               |
| 모든 배열을 반복 키로 직렬화                            | 유형과 상태에는 호환되지만 난이도 단일 값은 서버에서 여전히 스칼라가 되어 빈 배열로 변환되므로 제외했다. |
| 반복 키를 사용하고 난이도 단일 값만 두 번 전송          | 현 서버의 배열 계약을 지키면서 다중 값과 빈 값의 의미를 유지하므로 선택했다.                             |

## 결정

`/api/v2/problems` 요청은 반복 키 형식으로 직렬화하고, 난이도가 하나면 같은 값을 두 번 전송한다.

## 이유

서버의 난이도 필터는 `IN` 조건이므로 같은 값의 중복은 결과 집합을 바꾸지 않는다. 이 방법은 API 또는 도메인 모델을 바꾸지 않고 현재 서버의 배열 변환을 만족한다. 유형과 상태는 기존 DTO가 단일·다중 반복 키를 처리하므로 값을 중복하지 않는다.
