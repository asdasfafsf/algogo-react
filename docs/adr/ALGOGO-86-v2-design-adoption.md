# ALGOGO-86: React v2 디자인 적용 범위

## 문제

첫 shadcn 전환(PR #123) 이후 사용자가 `algogo-react-v2`의 디자인을 최종 기준으로 지정했다. v2에는 샘플 문제, 임시 로그인 전환, 에디터 자리표시자와 실제로 구현되지 않은 메뉴가 있으므로 화면 전체를 그대로 대체하면 기존 서비스 동작을 잃는다.

## 검토한 대안

| 대안 | 장점 | 문제 |
| --- | --- | --- |
| v2 앱 전체 교체 | 시각 결과를 그대로 재현 | 실제 API, 인증 복귀, Monaco, 코드·설정 저장 및 실행 흐름을 재구현해야 한다 |
| 기존 앱 위에 전역 CSS 덮어쓰기 | 빠르게 분위기 변경 | 컴포넌트 상태와 화면별 스타일이 충돌하고 유지보수가 어려워진다 |
| v2 디자인을 기존 표시 계층에 적용 | 기존 동작을 유지하며 디자인 재현 | 기존 컴포넌트별 스타일 대응이 필요하다 |

## 결정과 이유

v2의 색상·타이포그래피·간격·시각 요소를 기존 shadcn 표시 컴포넌트에 적용한다. 기존 API·도메인·라우팅·상태 계약은 유지하며, 레퍼런스의 샘플 데이터나 임시 동작은 가져오지 않는다. 메인 캐러셀의 슬라이드 구성과 조작 방식은 사용자 지시에 따라 보존한다. 기존 기능이 v2 시안에 없더라도 제거하지 않고 같은 시각 규칙으로 표현한다.

레퍼런스 디렉터리에는 사용자의 미커밋 변경이 있어 읽기 전용으로 사용한다. 구현은 별도 `ALGOGO-86` 워크트리에서 진행한다.
