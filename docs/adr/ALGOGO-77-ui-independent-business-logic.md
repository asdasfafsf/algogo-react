# ALGOGO-77: 디자인 교체를 위한 비즈니스 로직 경계

## 문제

UI는 shadcn을 기반으로 새로 디자인할 예정이지만 문제 조회·실행·저장·계정의 기존 동작은 유지해야 한다. 현재 훅, Zustand와 화면 컴포넌트 안에서 데이터 변환·판단과 API·소켓·모달 호출이 섞여 있어 UI 교체가 기능 재구현으로 이어진다.

## 검토한 대안

| 대안 | 장점 | 버린 이유 또는 제약 |
|------|------|-------------------|
| 기존 컴포넌트를 더 작은 컴포넌트로 분할 | JSX 복잡도 감소 | UI와 결합된 판단은 남아 새 디자인에서 재사용하기 어렵다 |
| 비즈니스 코드를 모두 커스텀 훅으로 이동 | React에서 호출하기 편하다 | React·스토어·모달 의존이 유지되며 순수 로직을 단독 검증할 수 없다 |
| 모든 API·상태·UI를 새 계층으로 일괄 재작성 | 일관된 새 구조 | 동작 변경 위험이 크고 이미 동작하는 transport까지 불필요하게 바꾼다 |
| 기능별 순수 코어와 외부 효과 경계를 단계적으로 분리 | 기존 화면을 유지하면서 독립 검증·교체 가능 | 연결 코드가 남고 순수성·동작 보존을 함께 검토해야 한다 |

## 결정

기능별 순수 TypeScript 코어를 `src/domain/`에 두고, 기존 훅·스토어는 API·소켓·브라우저·UI와 연결하는 어댑터로 단계적으로 얇게 만든다. 비동기 절차를 재사용할 필요가 있으면 명시적인 포트를 받는 application 모듈로 분리하되 순수 함수라고 부르지 않는다.

## 이유와 경계

핵심은 기존 디자인 보존이 아니라 기존 비즈니스 동작 보존이다. 순수 코어는 입력을 받아 결과·다음 상태·실행할 판단을 반환한다. React, Zustand, Axios, DOM, localStorage, 현재 시각·난수에 직접 의존하지 않는다. 필요한 시각·저장된 데이터는 호출자가 전달한다. 입력 객체를 수정하지 않는다.

네트워크 요청, 소켓 구독, 인증 정보 저장, 라우팅, 확인 모달 등은 순수하게 만들 수 없는 효과이므로 연결 계층에 둔다. 표시 컴포넌트는 필요한 값과 콜백을 받아 새 UI에서 바꿀 수 있도록 한다. 단순 스타일 계산까지 억지로 도메인에 옮기지 않는다.

리팩터링은 호출 경로에 실제로 연결하고 기존 동작을 특성화한 테스트로 검증한다. 발견한 버그·계약 변경은 별도 이슈에서 처리한다. 이번 단계에 백엔드 수정이나 shadcn 설치·디자인 교체는 포함하지 않는다.

## 새 디자인에서 재사용하는 경계

| 영역 | 순수 규칙 | 연결 계층 |
|------|----------|-----------|
| 문제 목록·오늘의 문제 | `domain/problems`의 검색 요청, 필터, 정렬, 페이지, 날짜, 진행률 | `hook/problem-list`, `hook/today-problem` |
| 문제 갱신 | 같은 날짜 여부 | `application/problems/updateProblem`의 주입된 확인·요청·알림·새로고침, `hook/problem/useProblemUpdate` |
| 에디터 | `domain/editor`의 코드 선택, 저장 만료, 요청 생성, 테스트 케이스, 템플릿 응답 판단 | 에디터 훅·스토어, `application/editor/execute`, `hook/editor` |
| 계정 | `domain/account`의 프로필 요청, OAuth 결과, 기여도 달력과 강도 | `application/account/oauthCallback`, `hook/me`, `MeStore` |

새 shadcn 화면은 기존 컨트롤러의 값·콜백을 연결한다. 모달 구현을 교체할 때에는 컨트롤러의 모달 어댑터를 새 구현에 연결한다. 모달·라우터·스토어를 포함하는 React 훅 자체를 순수 코어라고 간주하지 않는다. 스타일과 색상 매핑은 표시 계층에 둔다.

## 회귀 검증

Node 24 환경에서 저장소 루트 기준으로 다음 스크립트를 실행한다. 각 명령에는 프로젝트 규칙대로 `rtk`를 붙인다.

- `rtk proxy node tests/domain-boundaries.mjs`: 도메인과 전이 의존성의 React/외부 패키지/브라우저/현재 시각 접근 검사
- `rtk proxy node tests/problems-domain.mjs` 및 `tests/problems-update.mjs`: 문제 규칙과 갱신 흐름
- `rtk proxy node tests/editor-domain.mjs`: 코드 선택 우선순위, 템플릿 응답, 실행 재시도
- `rtk proxy node tests/editor-settings.mjs`: 설정 적용 순서·저장 여부·실패·취소
- `rtk proxy node tests/problem-initialization.mjs`: 예시 입력 초기 상태·코드 초기화 불변성
- `rtk proxy node tests/account-core.mjs`: 계정 요청, OAuth 결과, 윤년·기간·기여도 경계

의존 경계 검사는 정적 회귀 방지 장치이며 수학적 순수성을 증명하지 않는다. 별칭을 통한 간접 호출, 입력 변경, 시간대 정책은 코드 리뷰와 동작 테스트에서도 확인한다. 날짜 계산은 기존의 로컬 달력 또는 UTC 기준을 그대로 유지하고 현재 시각만 입력으로 전달한다.

## 남아 있는 연결과 검증 범위

API/소켓/저장소 구현, 라우팅, 모달 열기, 클립보드, 화면 크기·탭 선택은 외부 효과 또는 표시 상태로 유지한다. 기존 JSX를 모두 props 전용으로 바꾸는 것이 이 단계의 완료 조건은 아니다. 새 디자인에서 재사용할 업무 규칙과 흐름을 화면 밖으로 이동하는 것이 기준이다.

실제 OAuth 계정으로 로그인·프로필 저장·코드 실행·채점까지 확인한 것은 아니다. 이러한 경로는 주입한 응답을 이용한 흐름 테스트와 실제 서버 연동 검증을 구분한다. 기존 템플릿 수정 응답 분기처럼 의심스러운 동작도 특성화 테스트로 보존하며 별도 버그 작업에서 변경한다.
