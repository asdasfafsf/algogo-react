# ALGOGO-86: shadcn 전환에서 동작 경계 보존

## 문제

화면마다 자체 버튼, 메뉴, 모달을 구현하고 있어 디자인과 키보드 조작을 일관되게 개선하기 어렵다. 외형을 바꾸면서 이미 분리한 비즈니스 로직까지 다시 작성하면 저장·인증·실행 계약의 회귀 위험이 커진다.

## 검토한 대안

| 대안                                        | 장점                                      | 단점                                                        |
| ------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------- |
| 모든 호출부와 상태 관리를 한 번에 다시 작성 | 새 API로 일관됨                           | UI 전환과 업무 규칙 변경이 섞여 회귀 원인을 분리하기 어려움 |
| 기존 컴포넌트의 CSS만 변경                  | 변경량이 작음                             | 메뉴·모달 포커스 관리와 키보드 구현이 중복됨                |
| shadcn 기반 UI와 얇은 호환 컴포넌트         | 업무 콜백을 보존하면서 공통 상호작용 개선 | 구형 props를 받는 표시 계층이 당분간 남음                   |

## 결정과 이유

shadcn 구조의 Radix 기반 UI를 `components/ui`에 두고 기존 공용 props는 얇은 표시 어댑터로 연결한다. 복합 필터는 내부에 입력·다중 선택·적용 버튼이 있으므로 Menu의 문자 탐색·선택 닫기 대신 Popover를 사용한다. 단일 언어·템플릿 선택에는 DropdownMenu, 탭에는 Tabs, 모달에는 Dialog를 사용한다.

도메인, API, 저장소, 라우트 계약은 유지한다. 이벤트를 사용하지 않는 새 UI 콜백에는 값만 전달하며 가짜 DOM 이벤트를 만들지 않는다. Monaco와 MathJax는 전문 렌더러이므로 유지한다. 패널 드래그는 기존 크기 저장 동작을 보존한다. 파일 업로드 input은 브라우저의 파일 선택 계약을 유지한다.

DialogTrigger 없이 서비스에서 모달을 여는 기존 구조도 지원해야 하므로 공용 DialogContent가 호출 요소를 기억해 닫은 뒤 포커스를 복원한다. 호출부에서 지정한 autofocus 방침과 중첩 모달을 존중한다.

## 캐러셀 구조

사용자 지정에 따라 홈은 기존 안내 슬라이드를 담은 캐러셀로 유지한다. 고정 카드 분할 레이아웃으로 대체하지 않는다. Embla를 쓰는 shadcn Carousel에 기존 props, 이전/다음, 점 선택, loop, 자동 재생 간격, hover 일시 정지, 드래그, refs를 연결한다. 비활성 슬라이드는 inert로 포커스에서 제외한다. `transition`은 새 엔진의 애니메이션 duration으로 환산하므로 기존 CSS의 정확한 밀리초 곡선과는 다르다. 이는 표현 변경이며 슬라이드 데이터와 탐색 순서는 유지한다.

## 검증

회귀 테스트와 실제 로컬 UI 조작을 함께 수행한다. 외부 OAuth와 백엔드 오류 때문에 확인할 수 없는 성공 경로는 통과로 기록하지 않는다. 구체적인 실행 결과는 `docs/verification/ALGOGO-86.md`에서 관리한다.
