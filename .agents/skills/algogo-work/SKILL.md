# Algogo React 작업

입력은 `ALGOGO-{번호}` 또는 작업 설명이다. 먼저 대화에서 요청한 결과가 검토·설계인지 실제 변경인지 구분한다. 설계 의견이나 기술 선택에 대한 동의만으로 새 구현·이슈 생성을 시작하지 않는다. 이미 구현을 요청했거나 구체적인 실행 제안을 승인했다면 그 승인을 유지하고, 이후의 설계 조정을 작업 중단으로 해석하지 않는다. 구현이 요청되면 승인된 로컬 변경과 검증을 끝까지 수행한다.

확정된 선택, 아직 검토 중인 선택, 실제 변경 요청을 구분해 유지한다. 결과를 크게 바꾸는 모호함만 질문하고 그 답에 의존하지 않는 작업은 계속한다. 스킬 호출 자체를 추가 외부 작업의 승인으로 해석하지 않는다.

## 공통 지침

이 스킬은 Algogo React 프론트 저장소 전용이다. 다른 저장소는 해당 저장소의 지침을 확인하며, 프론트의 이슈·브랜치 규칙을 그대로 적용하지 않는다. 스킬 디렉토리를 기준으로 필요한 링크를 읽는다. 별도 워크트리로 이동한 뒤에는 그 워크트리의 루트 지침을 따른다.

1. [AGENTS.md](../../../AGENTS.md): 공통 지침, 명령 실행, 검증과 브랜치 보호.
2. [작업 절차](../../../docs/agents/work.md): 이슈 확인부터 워크트리, 구현, PR, 완료 처리까지의 기준 절차.
3. [Git 규칙](../../../docs/agents/git.md): 워크트리, 브랜치, 커밋, PR 형식. Linear 작업을 수행할 때는 [Linear 규칙](../../../docs/agents/linear.md)도 읽는다.
4. TypeScript/React 또는 스타일 수정 시 [코딩 규칙](../../../docs/agents/code.md).
5. 스킬·에이전트 지침 수정 시 [지침 관리](../../../docs/agents/workflow.md).

위 문서를 기준으로 실행하며 같은 규칙을 이 스킬에 복제하지 않는다. 기존 Claude `/work`의 `$ARGUMENTS`에 해당하는 입력은 Codex에서는 사용자의 스킬 호출 뒤에 붙은 요청과 대화에서 얻는다.

## 실행 환경 연결

- Linear 작업은 연결 도구를 우선 사용한다. 도구 미제공·연결 장애이면 프로젝트 규칙의 GraphQL API를 사용할 수 있다. 권한·승인 거절을 다른 경로로 우회하지 않는다. 키 값은 출력하지 않는다. 연결 실패는 사실대로 보고하며, 승인된 로컬 구현·검증까지 중단하지 않는다.
- 워크트리는 실제 Git 워크트리 경로를 확인하고 생성·사용한다. Claude 전용 `Agent(isolation: "worktree")`를 요구하지 않는다.
- 연결할 실제 이슈가 없으면 [로컬 준비 절차](../../../docs/agents/work.md#1-로컬-작업과-이슈-연결)에 따라 구현·검증한다. 기존 이슈가 있으면 새 이슈 생성 승인 없이 그 이슈를 연결할 수 있다. 외부 반영이 요청된 경우 필요한 승인 질문은 구체적인 변경과 이슈 초안을 준비한 뒤에 한다.
- 위임이 승인되었으면 제공되는 에이전트 도구를 사용하고 담당 워크트리와 수정 범위를 명시한다. 그렇지 않으면 직접 진행한다.
- 기존 작업을 이어가는 경우 브랜치·워크트리·PR·이슈의 현재 상태를 확인해 이어간다. 이미 완료된 단계를 반복하거나 중복 생성하지 않는다.
- 검증 실패나 외부 연결 문제로 완료하지 못한 단계는 명시한다. 실제 머지 완료 전에는 이슈를 Done으로 표시하지 않는다.

결과에는 실제 변경과 검증 결과, 워크트리 경로를 한글로 보고한다. 브랜치·PR·이슈가 있으면 함께 안내하고, 로컬 완료와 외부 반영 여부를 구분한다. 검토·설계 요청에는 그 결과만 보고하며 구현 승인을 얻기 위한 질문으로 자동 전환하지 않는다.
